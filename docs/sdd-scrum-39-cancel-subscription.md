# SDD: SCRUM-39 — Отмена автопродления подписки в один клик

**Статус:** реализовано по тексту задачи  
**Поток:** А — рекуррент и эквайринг  
**Трекер:** Кузьменко Степан. В бэклоге: Чубаров Егор.

Списание и dunning: `docs/sdd-scrum-36-recurring-payments.md`, `docs/sdd-scrum-38-dunning-management.md`. Планировщик: `docs/sdd-scrum-37-billing-scheduler.md`.

---

## 1. Контекст

Подписка живёт в `subscriptions` со статусами `active`, `past_due` и `cancelled`. Планировщик берёт `active` и `past_due`, у которых наступила `next_billing_at`. Нужен один вызов, которым владелец останавливает будущие автосписания и получает подтверждение, в том числе письмом.

## 2. Цели (DoD)

1. `POST /api/v1/subscriptions/{id}/cancel` отменяет только подписку владельца. Чужая подписка — 403.
2. Статус становится `cancelled`, планировщик эту строку больше не берёт.
3. Повторный вызов возвращает тот же статус без ошибки.
4. Эндпоинт покрыт тестами.

## 3. Не-цели

- Отдельная ссылка отмены без входа. В задаче «email/токен» — это учётная запись access-токена: id из JWT и email этой записи как адресат письма.
- Возврат уже оплаченного периода и отвязка `payment_method_id` в ЮKassa.
- Новые колонки. Время отмены — существующий `updated_at`.
- Второе письмо и сдвиг `updated_at`, если подписка уже `cancelled`.
- Отмена чужого списания, которое уже прошло проверку статуса и держит строку. Оно доигрывает. Закрывается следующий период.

## 4. Решение

| Тема | Выбор |
|------|--------|
| URL | `POST /api/v1/subscriptions/{subscription_id}/cancel`. Тело запроса не нужно |
| Кто вызывает | `CurrentUser`: Bearer access JWT. Нет токена, просрочен, неверный или пользователь неактивен — 401, как у `/me/*` |
| Чужая подписка | 403 `Forbidden`, строка не меняется. Так требует DoD: существование чужого id и отказ различаются |
| Нет подписки | 404 `Subscription not found`. id вне `1 … 2^63-1` — 422 |
| Кого можно отменить | `active` и `past_due`. Оба попадают в `lock_next_due_for_billing`. `cancelled` уже вне выборки |
| Запись | `status=cancelled`, `updated_at` — время отмены с таймзоной. `next_billing_at`, `dunning_attempts` и `payment_method_id` не трогаем: планировщик фильтрует по статусу, токен в ответе и письме не нужен |
| Идемпотентность | Уже `cancelled`: 200, прежние `status` и `updated_at`, без `UPDATE` и без второго письма |
| Блокировка | `get_for_update` до решения. Отмена ждёт транзакцию списания. После `commit` новое списание видит `cancelled` и в ЮKassa не идёт |
| Чужой ряд | После проверки владельца блокировка снимается `rollback`, чтобы не держать чужую строку до конца ответа |
| Транзакция | Успех — `commit` в сервисе, затем письмо. Отказ SMTP и ошибка постановки задачи ответ не меняют: подписка уже `cancelled` |
| Письмо | Отдельное от dunning. Тема «Автопродление подписки №… отменено». Адрес — email владельца из `users`. Ошибка SMTP пишется в лог, без email и без `payment_method_id` |
| Ответ | `{id, status, updated_at}`. `payment_method_id` и маска карты не возвращаются |
| Слои | Роут переводит исключения в HTTP. Сервис не импортирует FastAPI |

Потеря письма при падении SMTP такая же, как у dunning: повторный вызов письмо не дублирует, отдельной колонки «письмо отправлено» нет.

## 5. Интеграция

| Место | Действие |
|-------|----------|
| `app/api/v1/subscriptions.py` | Роут |
| `app/services/subscription_cancellation.py` | Проверка владельца, статус, очередь письма |
| `app/services/email.py`, `templates/email/subscription_cancelled.html` | Письмо подтверждения |
| `app/schemas/subscription.py` | Ответ |
| `app/main.py`, `app/api/openapi.py` | Маршрут и описание в Swagger |
| Схема БД, планировщик, `charge_subscription` | Без изменений: `cancelled` уже исключён |

## 6. Тесты

База `awe_test`. SMTP и ЮKassa не вызываются по-настоящему.

- Без токена и с неверным токеном — 401. Чужой владелец — 403, статус и `updated_at` прежние, письма нет.
- Нет id — 404. Ноль и слишком большой id — 422.
- `active` и `past_due` становятся `cancelled`, `updated_at` равен переданным часам, токен оплаты не попадает в JSON и лог.
- Повтор возвращает то же `updated_at` и шлёт письмо один раз. Уже отменённая строка письмо не получает.
- Ошибка постановки письма и ошибка SMTP не откатывают отмену.
- После отмены `run_billing_tick` списывает только соседнюю due-подписку. `charge_subscription` на отменённой не вызывает кассу.
- Отмена ждёт чужой `FOR UPDATE` по этой строке.
- Письмо говорит, что автосписаний больше не будет, и экранирует email в HTML.

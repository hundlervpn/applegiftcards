# SDD: SCRUM-37 — Фоновый планировщик регулярных списаний

**Статус:** реализовано по тексту задачи  
**Поток:** А — рекуррент и эквайринг

Списание одной подписки: `docs/sdd-scrum-36-recurring-payments.md`.

---

## 1. Контекст

`charge_subscription(session, subscription)` списывает конкретную активную строку и сам делает `commit` или `rollback`. Выборка `list_active_due_for_billing` строку не блокирует. Нужен процесс, который в работающем приложении периодически находит подписки со статусом `active` и `next_billing_at <= now()` и вызывает это списание. Несколько воркеров не должны списать одну и ту же подписку дважды.

## 2. Цели (DoD)

1. Планировщик стартует и останавливается в lifespan FastAPI. После остановки не остаётся ни задачи планировщика, ни открытой сессии.
2. Выборка подписки к списанию — `FOR UPDATE SKIP LOCKED`.
3. Ошибка одной подписки пишется в лог и не останавливает обработку остальных в этом проходе.
4. Тесты перематывают время подставными часами, без ожидания реального интервала.

## 3. Не-цели

- APScheduler и новая зависимость.
- Dunning: `past_due`, рост `dunning_attempts`, отдельная пауза между отказами кассы. Это остаётся на `charge_subscription`.
- Несколько успешных периодов одной подписки за один проход.
- Изменение контракта `charge_subscription` и схемы БД.

## 4. Решение

| Тема | Выбор |
|------|--------|
| Движок | Один `asyncio.Task` в `app/services/scheduler.py`. Цикл: проход, затем пауза. Второго прохода в том же процессе нет |
| Старт | Lifespan создаёт задачу `billing-scheduler` до `yield`. Первый проход сразу, без ожидания интервала |
| Интервал | `Settings.billing_scheduler_interval_seconds`, по умолчанию `600`. Пауза считается после конца прохода. Переменная окружения `BILLING_SCHEDULER_INTERVAL_SECONDS` |
| Остановка | `asyncio.sleep` отменяется сразу. Уже начатый `charge_subscription` доигрывает под `asyncio.shield`: на время этого вызова и закрытия сессии счётчик отмены снимается и затем возвращается, поэтому цикл не переходит к следующей подписке. После задачи — `dispose_engine()` |
| Кого берём | Один ряд за раз: `status = active`, `next_billing_at <= now()`, порядок `next_billing_at, id`, `LIMIT 1`, `FOR UPDATE SKIP LOCKED`. Метод `SubscriptionRepository.lock_next_due_for_billing`. `list_active_due_for_billing` не блокирует и не меняется |
| Сессия | Новая сессия на каждую попытку. Блокировка и `charge_subscription` — одна транзакция, своего `commit` между ними нет. Чужих незакоммиченных изменений в сессии нет: в ней только эта строка |
| Повтор в том же проходе | Id уже взятой в этом проходе подписки исключается из следующей выборки. Отказ кассы не двигает `next_billing_at`, без исключения проход зациклился бы. Следующий проход, через интервал, пробует строку снова. Успех, после которого дата всё ещё в прошлом, тоже ждёт следующего прохода: одно списание подписки за проход |
| Ошибка подписки | `RecurringChargeError` — `logger.warning` с id и именем исключения, без текста исключения и без traceback. Любое другое — `logger.exception` с id. Если сессия всё ещё в транзакции, `rollback`. Проход идёт к следующей подписке |
| Сбой всего прохода | Ошибка выборки логируется, задача планировщика не умирает, следующий проход — после интервала |
| Часы | В планировщик передаются `now` и `sleep`. По умолчанию `datetime.now(timezone.utc)` и `asyncio.sleep`. Тесты подставляют свои |
| Списание | Аргумент `charge`, по умолчанию `charge_subscription` |

`as_of` без таймзоны — `ValueError`, как у соседней выборки.

## 5. Интеграция

| Место | Действие |
|-------|----------|
| `app/services/scheduler.py` | Цикл, один проход, остановка текущего списания |
| `app/repositories/subscriptions.py` | `lock_next_due_for_billing` |
| `app/config.py` | Интервал |
| `app/main.py` | Старт и остановка задачи в lifespan, затем `dispose_engine` |
| Роуты, схема, `charge_subscription` | Без изменений |

`TestClient` входит в lifespan. В `tests/conftest.py` планировщик на приложении заменён пустой корутиной, иначе прогон тестов списал бы подписки из dev-базы. Тест самого lifespan подставляет свою задачу и проверяет её старт и остановку.

## 6. Тесты

База `awe_test`. ЮKassa в тесте настоящего `charge_subscription` замокана.

- Проход вызывает списание только для `active` с `next_billing_at <= now`, от старых к новым.
- `past_due`, `cancelled` и будущая дата не списываются.
- Вторая транзакция со `SKIP LOCKED` не получает строку, уже взятую `FOR UPDATE`. Соседняя незаблокированная строка ей достаётся. `list_active_due_for_billing` эту занятую строку по-прежнему видит.
- Отказ одной подписки не мешает следующей. Предупреждение не содержит id платёжного метода.
- Подписка, которая после попытки всё ещё due, в том же проходе второй раз не берётся и берётся на следующем.
- Сдвиг подставных часов между проходами добавляет в выборку подписку, у которой наступил срок.
- Отмена во время паузы не начинает следующий проход. Отмена во время списания даёт этому списанию завершиться и закрывает сессию.
- Падение прохода не останавливает цикл.
- Lifespan поднимает задачу `billing-scheduler` и при выходе сначала дожидается её, потом освобождает движок.
